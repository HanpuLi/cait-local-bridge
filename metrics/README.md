# OSS metrics snapshots

These files are auditable snapshots, not targets and not a substitute for source APIs.

- `contributors.json` is generated by `scripts/contributor-metrics.py`. It counts unique external authors of merged pull requests in ScopeRail's rolling 12-month window and excludes the repository owner and obvious bot accounts.
- `oss-health.json` records ScopeRail repository/publication health and explicitly keeps unsupported dependency metrics unavailable.
- `claude-oss-account.json` is generated by `scripts/claude-oss-account.py`. It audits the maintainer account across all public source repositories: external merged PRs, per-repository external human contributors, observable general-eligibility facts, and optional OpenSSF criticality measurements.

Refresh the GitHub-backed snapshots with:

```sh
python scripts/contributor-metrics.py
python scripts/claude-oss-account.py
```

Refresh ScopeRail health with:

```sh
python scripts/oss-health.py
```

For OpenSSF measurements, pass the official `criticality_score` executable:

```sh
python scripts/oss-health.py --criticality-command /path/to/criticality_score
python scripts/claude-oss-account.py --criticality-command /path/to/criticality_score
```

Both scripts deliberately use `-depsdev-disable` for a credential-free GitHub-signal measurement and label it accordingly. They do not present that measurement as the full deps.dev-enriched default score.

When a source cannot provide a reliable dependent/download count, keep the value unavailable rather than replacing it with zero.

Do not create trivial pull requests, artificial dependents, repeated downloads, fake contributors or other activity merely to change these numbers.
